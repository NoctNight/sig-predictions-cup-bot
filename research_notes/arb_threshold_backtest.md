# Set-arb return threshold backtest (paper, SIG quotes)

Generated by `python3 -m sigbot.backtest_arb`. Data: `venue_quotes` venue='sig', 322 polls, 2026-10-21 23:49 to 2026-10-22 07:37 UTC (7.8 h), 117 races (3 with an Independent leg). Order sizes in the table are ABSENT (bid_sz/ask_sz are NULL), so top-of-book size is assumed.

## Method and limitations

* venue_quotes stores a row only when a leg's quote changes; the full state at each poll is rebuilt by forward-filling each leg's last bid/ask. Polls with no change anywhere are not logged (state is unchanged, so no new opportunity), but the first poll must already contain all legs.
* Sell-set: sum(bids) > 1, edge = sum_bids - 1, cost = n - sum_bids. Buy-set: sum(asks) < 1 - x, edge = 1 - sum_asks - x, cost = sum_asks (x from params/x_live.json by_race, default 0.003, 0 for races with an Independent leg). Buy-set profit is an EXPECTED value (it loses everything if no listed party wins), sell-set profit is locked.
* Entry when return >= threshold, ranked by return, size = assumed top-of-book size capped by 25,000 total / 5,000 per race, minimum 20 sets, at most one capture per race per poll. Threshold 0.0% means any positive edge (the live bot additionally requires an absolute edge of 0.5c and uses min_ret 1.5%; neither floor is applied here).
* Free unwind: held sell-sets are closed when sum(asks) <= 1 (proceeds n - sum_asks >= payout n - 1). The brief wrote `<= n_legs - 1`; that equals `<= 1` only for 2-leg races, and for a 3-leg race it would unwind at a loss, so the payout-based rule from sigbot/arb.py is used. Unwinds are FIFO, at most the assumed top size per race per poll, and realise entry sum_bids - sum_asks per set.
* Held sets are valued at locked profit at the end of data. Window metrics divide by capital-hours inside the observation window only; held sets keep their capital locked until settlement (2026-11-04 17:00 UTC), so the `to settle` column also charges that capital for the remaining time. That is the fair comparison across thresholds, because the window metric rewards sets that merely have not matured yet.
* LIMITATIONS: (1) our trades do not move later polls: a standing mispricing is assumed to refill to the assumed size every poll, so it is re-captured each poll until a cap binds. This is the main source of optimism; the `no re-stack` runs enter a race once per continuous run of qualifying polls instead. (2) Sizes are assumed (500, and 2,000), not observed. (3) Fills are assumed at the logged touch with no latency, no fees, no allOrNone rejection (the live log has 8 rejected arb orders out of 22). (4) The window is only 7.8 hours, a single evening, so thresholds are compared on one regime and a few races (see concentration below). (5) Unwinding only considers the top of the ask book. (6) Quotes come from a 60-120 s poll, so intra-poll opportunities are invisible.
